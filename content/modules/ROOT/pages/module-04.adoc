= Configuring the Container

The RHEL Web Console's creation form shows the complete container specification before anything runs — every port mapping, volume mount, and environment variable visible together in one view. Using the Podman CLI the same configuration would be assembled incrementally as flags on a single command, with the full picture only recoverable afterward via `podman inspect`.

In this module you'll configure `hostinfo-app` with a volume mount and an environment variable, review the full specification in the creation form, and observe the effect in the running application.

`hostinfo-app` has a *Host View* mode that shows information about the system the container is running on. Enabling it requires providing two things the container cannot discover on its own: the host's hostname via an environment variable, and the host OS information via a file mount.

== Remove the Running Container

If `hostinfo` is still running from the previous module, select the three-dot menu (⋮) and select *Delete*.

== Find the System Hostname

Select *Overview* in the left navigation. The system hostname appears in the *Configuration* section of the page.

image::find_hostname.png[Cockpit Overview page with hostname visible in the Configuration section]

Note the hostname — you will enter it as an environment variable in the next step. Select *Podman containers* to return.

== Create the Configured Container

In the *Images* panel, select *Create container* from the `hostinfo-app` row. The *Name* field sits above the tabs.

* *Name* — `hostinfo`

**Integration tab** — add the following in order:

* Select *Add port mapping*
** *Host port* — `8000`
** *Container port* — `8000`
** *Protocol* — `TCP`

* Select *Add volume*
** *Host path* — `/usr/lib/os-release`
** *Container path* — `/host/os-release`
** *Writable* — leave unchecked (read-only)
** *SELinux* — leave as `No label`

* Select *Add variable*
** *Key* — `HOST_HOSTNAME`
** *Value* — the hostname from the Overview page

image::create_configured.png[Integration tab showing port mapping, volume mount, and environment variable configured together before creation]

Before selecting *Create and run*, review what the form shows. The port the container will be reached on, the host file it can read, and the variable it will receive are all listed in one place before the container exists.

Select *Create and run*.

== Verify the Configuration

Open http://hostinfo-{guid}.{domain}[*the hostinfo application*^]. Select the *Host View* toggle.

image::host_view.png[hostinfo-app Host View showing hostname and OS distribution populated from injected resources]

The hostname populates from the `HOST_HOSTNAME` variable. The OS distribution populates from the `os-release` file. Each piece of information came from a resource explicitly provided — nothing the container can see was made available by accident.

In Cockpit, expand the `hostinfo` container row and select the *Integration* tab to see the port mapping, volume mount, and environment variables as the container sees them.

image::details_with_env.png[Integration tab showing active port mapping, volume mount, and injected environment variables]

== What the Form Made Visible

Using the Podman CLI, this configuration would require multiple flags assembled one at a time — port, volume with options, environment variable — and the complete picture is only available after the container exists via `podman inspect`. The creation form collects the same information upfront as a structured specification, making the full configuration visible and auditable before anything runs.
